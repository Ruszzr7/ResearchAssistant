# 开发进度

> 只记录当前状态、里程碑和验证基线；完整历史与 diff 由 Git 保存。

## 当前状态

- 论文研究页已切换到持久化通用 Agent：统一 Turn 输入、原生 Tool Calling、自然语言澄清、严格 cite、ActionTicket 回执和刷新恢复共用一条写链路。
- 论文理解由用户打开论文后手动启动；优先达到 `PROFILE_READY`，连续三次真实失败且本地来源可读时才开放明确的受限兜底。
- 对话与文档解析使用双角色模型配置；图片能力必须实测通过，原生 PDF 由连接测试自动探测，不显示 Token 或成本。
- 当前实现不使用 Embedding、向量数据库或独立 RAG；论文事实通过版本化本地来源的确定性搜索、读取、逐字引用和页面定位完成。
- 同一论文可建立多个上下文完全隔离的对话；只共享论文来源和画像，不共享消息、摘要、指代焦点或选区。
- 旧 Workbench run/step、大路由、分类器和重复会话写链路已删除；确定性选区/公式区域能力继续作为 PDF 输入工具保留。
- PDF.js 负责渲染，PDFium 负责选择和搜索，PDFBox 负责服务端版面事实。
- 论文事实由当前 PDF 版本的本轮 evidence 支撑；会话历史和论文画像只帮助理解与检索。
- PDF 页面操作覆盖高亮、下划线、笔记、批注和跳转；所有目标由服务端当前版本来源解析，成功以客户端真实回执为准。
- 项目简化已移除写作助手、旧独立论文对比、Gap 分析、自然语言计划、BibTeX/Obsidian/Zotero 导出、引用网络扩展和废弃的 RAG 诊断；论文研究页保留“添加对比文献”入口，等待后续统一实现。
