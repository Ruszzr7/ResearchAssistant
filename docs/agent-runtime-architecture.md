# Agent 运行时架构

## 目标

单论文 Agent 在多轮检索和页面操作场景中保持稳定：模型始终收到可预测、受预算约束的上下文；回答内容与页面操作各自生成一次，并在真实客户端回执后形成一条最终助手消息。运行上限只作为故障保护，不参与 Skill 路由或业务判断。

## 职责边界

| 组件 | 唯一职责 | 不负责 |
|---|---|---|
| `AgentContextAssembler` | 从会话、论文、附件和选区组装语义上下文 | 截断模型请求、保存工具过程 |
| `AgentConversationSummaryService` | 汇总普通用户/助手对话，形成跨轮记忆 | 汇总运行状态、操作回执和工具日志 |
| `AgentRunContextHarness` | 将完整运行记录确定性投影为模型视图，并独占输入预算 | 修改持久化记录、决定调用哪个 Skill |
| `LangChain4jPaperAgentExecutor` | 执行模型/工具循环，并在 `finish_research` 后获取最终 Markdown | 强制制造答案、解释页面操作是否成功 |
| `RunOutputState` | 保存本轮内容依据和已校验的页面操作计划 | 执行页面操作、持久化长期状态 |
| Action Ticket / Receipt | 由前端执行操作，后端校验回执并生成最终状态 | 让模型声称操作已经完成 |

## 上下文链路

1. Assembler 读取最近四个完整语义对话轮次、当前问题、论文上下文、附件和选区。运行状态与操作回执不进入对话记忆。
2. 模型和工具调用的完整记录保留在运行时 transcript 中，作为审计依据。
3. 每次请求前，Harness 都从完整 transcript 重新生成同一套模型视图，不依赖“之前是否发送过”之类的隐式状态：
   - 论文画像压缩为规划摘要；
   - 论文证据压缩为带 `sourceObjectId` 的证据卡；
   - Skill 激活结果压缩为激活状态；
   - 操作计划和最终整理结果保留推进协议所需的状态、引用映射和指令。
4. 当前轮已经消费的工具往返被折叠为一份确定性的工作状态，保留已激活 Skill、论文画像、去重后的证据卡、Need 进度和操作计划；最近两次工具往返保持原样，便于模型准确处理刚返回的结果。
5. 若请求超过 16,000 个估算输入 token，Harness 依次减少工作状态中的证据正文，再删除最旧的完整历史轮次。只有当前问题或附件本身仍无法容纳时才拒绝请求。

工具不会因“调用成功一次”或达到某个业务次数而退出可用集合。画像和完全相同的证据请求采用语义幂等：首次结果继续保留在工作状态中，重复请求只返回 `already_available`，不重复读取，也不改变 Agent 对其它工具的选择。改变目标、Need、查询条件或游标仍会正常执行。只有 `finish_research` 成功后才关闭研究工具并进入最终回答阶段。

这套投影是确定性的：同一 transcript 在任意模型调用次数下得到相同模型视图，避免证据随着调用次数累计膨胀，也避免第二次调用丢失关键状态。

## 输出链路

`paper_action` 只接收并校验页面操作计划。它不会保存回答、决定输出形式，也不会宣称页面已经执行。

`finish_research` 是输出协议的唯一入口：它同时声明内容依据 `PAPER`、`GENERAL_KNOWLEDGE` 或 `MIXED`，以及输出形式 `CONTENT`、`ACTION_ONLY` 或 `CONTENT_AND_ACTION`。论文依据模式要求本轮已经读到可用原文证据；包含页面操作的输出要求已有操作计划，已有操作计划也不能声明为纯内容。校验成功后关闭工具，下一次模型响应直接生成唯一的最终 Markdown。

“完成后告诉我结果”属于操作回执，不构成独立内容回答，因此使用 `ACTION_ONLY`。`CONTENT_AND_ACTION` 只用于用户还要求论文解释、总结或其他独立回答的场景；其内容草稿不描述操作状态，回执负责追加真实结果。

三种结果按同一状态机处理：

| 用户需求 | 模型产物 | 最终消息产生时机 |
|---|---|---|
| 仅回答 | 最终 Markdown | 内容生成并完成引用绑定后 |
| 仅操作 | 页面操作计划 | 客户端提交有效回执后，由后端生成操作结果 |
| 回答并操作 | 最终 Markdown + 页面操作计划 | 客户端提交有效回执后，由后端合并内容与操作结果 |

操作票据是待执行状态，客户端回执是执行成功的唯一依据。重新进入论文页面时，前端可以领取尚未完成的票据继续执行；后端不会把 `WAITING_CLIENT` 误记为成功。

## 运行边界

`AgentRunBudget` 统一提供运行级保护：研究阶段默认最多 10 次决策调用、12 次物理模型请求（额外保留 1 次 `finish_research` 决策和 1 次无工具最终回答）、12 次工具调用、160,000 个累计 token、900 秒总时长。最终输出阶段不能重新调用工具，也不能重复生成。单次模型请求超时由模型客户端负责，总运行时长始终大于单次请求时长，并为工具调用、最终回答和持久化保留时间。这些上限不决定是否调用画像、证据或操作 Skill。

## Skill 语义

- `paper-profile` 提供全局结构和规划线索。
- `paper-evidence` 读取支持论文事实的原文证据。
- `paper-action` 规划需要前端执行的跳转、高亮等页面操作。

画像与证据可以同时合理触发，因此评测同时记录必需集合与允许集合。生产运行时不规定三个 Skill 的顺序和次数，不使用问题关键词或具体案例规则；模型根据当前问题与工作状态自行选择，Harness 只负责幂等、上下文投影、权限校验和异常上限。

## 验收边界

单元测试验证确定性上下文投影、重复证据预算、旧历史轮次删除、最终引用协议、回答/操作组合及真实回执合并。页面操作评测默认等待浏览器执行并由后端收到回执后才记录成功；需要真实选区的案例必须从浏览器发起。指标数据生成与本架构构建分开执行。
