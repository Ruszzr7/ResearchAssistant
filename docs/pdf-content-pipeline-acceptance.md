# PDF 内容管线验收规范

## 目标

同一份 PDF 必须同时支持：可追溯的 LLM 理解、精确文本/公式选取和可定位的全文搜索。视觉交互使用 PDF.js，语义结构使用 PDFBox；两者通过 PDF hash、页码、原始文字项编号、字符范围和归一化坐标对齐，不要求单个解析器承担全部职责。

## 不变量

- 每个产物绑定原始 PDF SHA-256 和解析器版本；PDF 更新后旧索引、锚点、结构画像和记忆全部失效。
- PDF.js 文字项使用原始 `itemIndex`。空白项可以不参与匹配，但不能压缩后续编号。
- 规范化搜索字符必须能反向映射到 `itemIndex + charOffset`，页面高亮不得依赖压缩后的 DOM 序号。
- 所有持久化坐标明确声明坐标空间，并能在 CSS、viewport、归一化页面和 PDF point 之间往返。
- 选区原文、页面可见文字、后端 SelectionAnchor 和发送给 LLM 的当前证据必须一致。
- LLM 论文事实只引用当前 PDF 版本中可回到页码和区域的 evidence ID；摘要和记忆不能覆盖原始证据。
- 无文字层、单页提取失败和低质量解析必须分别报告，不能统一伪装成“无搜索结果”。

## 黄金样本

前端确定性样本位于 `frontend/tests/fixtures/pdf-content-golden.json`，覆盖空白文字项编号漂移、断词/连字、无文字层、同栏跨行选择、跨栏拒绝和公式区域缩放不变性。后端结构与 evidence 黄金样本继续使用 `backend/src/main/resources/eval/pdf-workbench-golden.json`；真实 PDF 只通过环境变量 manifest 引用，不提交本地路径或受版权保护正文。

## 验收矩阵

| 能力 | 确定性验收 |
|---|---|
| 搜索 | 查询、结果片段、页码、精确字符高亮和页内滚动目标一致；上下结果循环稳定 |
| 文本选择 | 起止字符、拼接原文、视觉栏、quads 和后端锚点一致；跨栏歧义明确拒绝 |
| 公式框选 | 50%–200% 缩放下归一化区域不变；后端原 PDF 裁剪与所见区域一致 |
| 结构解析 | 标题、作者、摘要、章节、正文、公式、图表、参考文献和页眉页脚角色可验证 |
| LLM 上下文 | 当前选区优先；每条事实引用当前版本 evidence；引用可跳回页码和 bbox |
| 异常降级 | 无文字层、提取失败、低置信度和过期版本具有不同且可恢复的状态 |

## 阶段门禁

每个阶段执行 `Plan → Execute → Test → Review → Commit`。阶段测试必须包含与本阶段直接相关的黄金契约；最终阶段再执行前后端全量测试、生产构建、真实 PDF 浏览器验收和无模型确定性评测。
