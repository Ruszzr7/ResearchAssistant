# PDF 交互事实层重构

## 目标

PDF 阅读器不再自行猜测栏、行和公式边界。字符顺序、字形命中、选区矩形和全文搜索统一由成熟 PDF 引擎提供；项目代码只负责界面状态、业务锚点、数学语义补全和 LLM 证据组装。

渲染与交互事实层分离：现阶段保留 PDF.js canvas 渲染，以降低迁移风险；交互事实层通过窄接口接入 PDFium/WASM。以后更换引擎时，上层批注、助手和后端契约不感知具体实现。

## 八阶段交付边界

1. 固化真实失败样本与可提交的合成基线。
2. 建立可替换的 PDF 交互引擎适配层，自托管 WASM，不依赖云服务。
3. 用引擎字符命中和搜索替换 PDF.js DOM/自研分栏推断。
4. 统一字符范围、页面矩形和文档指纹锚点。
5. 基于精确字符范围和字体/字形元数据切分正文、段内数学与独立公式。
6. 建立可替换的 LaTeX 转写链；本地确定性结果与不可确认结果严格分级。
7. 将原文、数学片段、LaTeX 状态和原页坐标作为结构化证据交给 LLM。
8. 删除旧启发式实现，执行完整回归与真实 PDF 视觉验收。

## 真实回归样本

真实论文不进入 Git。运行者通过 `RA_PDF_INTERACTION_SAMPLE` 指向本地 PDF；当前本机样本为 16 页 IEEE 双栏论文，关键页面是第 3 页。

验收必须覆盖：

- 右栏数学密集段落从 `where p_c` 起选择，不吸入同高度左栏内容；
- 公式上方或下方正文可以独立选取；
- 独立公式可形成连续字符范围和页面矩形；
- 搜索 `global power coefficient` 命中第 1、3、7、10、12 页，其中第 3 页可跳转并高亮；
- 选区原文由引擎字符范围回读，不由前端矩形重新拼接。

`frontend/tests/fixtures/pdf-interaction-golden.json` 保存不受版权限制的几何/契约基线。真实样本只保存短查询和预期指标，不保存论文正文、路径或截图。

## 关键约束

- 默认部署不要求 GROBID、OCR 服务或外部付费 API。
- PDF 有可靠文字层时不做整页 OCR；扫描件明确降级为无文字层状态。
- PDFium/WASM 随前端静态资源发布，运行时不从 CDN 获取核心二进制。
- 每个锚点至少绑定 PDF 指纹、页码、引擎字符范围和归一化页面矩形。
- LaTeX 只是数学语义派生物，不能覆盖或替代 PDF 原文事实。
