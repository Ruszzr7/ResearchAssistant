# 知识总结

> 只记录稳定、可复用的设计结论；日期、测试数字和完整变更由 `progress.md` 与 Git 保存。

## 工程与数据

- 本地单机优先，不为形式引入微服务、Redis、图数据库或第二套状态系统。
- Controller 管协议，Service 管业务，Mapper/Entity 管持久化；长任务返回 `taskId`。
- Flyway 目录是唯一数据库结构真源；删除已发布领域对象只能新增迁移，不能改写历史迁移。
- 测试使用独立 H2；旧库升级前先备份和核验，禁止对未知 schema 盲目 baseline。
- 删除 Java 类后的最终验证必须执行 `mvn clean test`，避免 `target` 残留 class 造成假通过。
- 研究会话、Agent Turn/Run/ToolCall 和异步任务是不同生命周期：会话恢复可见对话，Turn 表达一轮用户目标，Run 保存模型循环，ToolCall 审计工具与副作用，异步任务表达后台论文理解状态。
- 源码、配置和文档统一使用 UTF-8；PowerShell 读取中文文件显式指定 `-Encoding utf8`。

## PDF 事实层

- PDF.js 只负责 canvas 渲染；PDFium 统一负责字符命中、字符范围、选择矩形和全文搜索，禁止再从 TextLayer DOM 推断阅读顺序或分栏。
- 浏览器锚点由 `PDF fingerprint + page + charStart/charEnd + normalized rects` 标识，缩放不改变字符范围和归一化坐标。
- PDFBox 负责服务端版面 block、角色、阅读顺序和几何；版面质量问题由本地质量检测标记，并交由后续论文理解恢复，不调用外部解析器。
- 版面角色与内容精度分开：`TEXT` 可引用原文，`STRUCTURED` 可提供可信结构，`REGION` 只能证明页面区域。
- 文本能否精确映射与能否支撑论文事实是两个维度；参考文献可精确选择，但其证据用途仍可受限。
- 原文匹配先做 Unicode NFKC、连字、软连字符和空白归一化，同时保留回原始 UTF-16 偏移的映射。
- 数学密集正文不是扫描件。先复用 PDF 字符事实，再提供 `READY / APPROXIMATE / UNAVAILABLE` 的 LaTeX 辅助；近似 LaTeX 不能替代原文。
- 公式精确框选是默认选择不足时的后手。图像转 LaTeX 只在用户点击固定后按需执行，候选必须确认后才能成为证据。
- 编号公式必须形成独立、版本化的来源实体，并显式区分“公式定义/正文提及”以及“定理结果/证明步骤”。关系由版面顺序、标题和局部结构确定，不能让模型仅凭相似文字决定点击目标。
- 单双栏不是两套长期上下文。服务端只在局部归属阶段使用页码、栏位重叠和阅读顺序，防止跨栏把公式归给错误的定理/引理；归属完成后按论文逻辑顺序统一为同一来源索引。
- 公式视觉输入优先复用已确认缓存和版面结构；客户端裁图不可信，服务端需校验尺寸、类型和当前 PDF 版本。
- 有文字层时不做整页 OCR；扫描件或不可恢复二维结构应明确降级，不能伪装成精确文本。

## 论文理解、上下文与记忆

- 论文记忆分为事实层和可重建语义层：结构只引用稳定 block，摘要和画像不能覆盖原文。
- 缓存身份至少包含 paperId、PDF hash、解析版本和 schema/pipeline 版本。
- 全文理解按实际输入大小选择单次或少量大块处理；分块逐项保存检查点，修复调用不重发整篇论文。
- 手动论文理解入口不能依赖 readiness 成功才渲染。旧版面缓存不可读或状态请求暂时失败时，界面仍应显示可重试入口；服务端 readiness 不应为读取完整旧制品失败而返回 500，理解任务负责按当前版本重建缓存。
- 当前问题优先级最高；当前选区是只用于下一条消息的可选附件；对话历史、画像和长期观察只帮助理解和检索。
- `conversationId` 定义连续对话边界。新对话使用新 ID；清除选区不清除历史；新主题不得被上一轮 evidence 压制。
- 对话连续性和证据焦点是两个决策：同一论文、同一 `conversationId`、同一 PDF 版本的有界历史始终提供给模型；只有指代、省略、备选/排序、原因/展开或技术主题连续时才作为检索扩展和上一轮 evidence 弱提示。
- 自由文本不应先被固定大路由归类；通用 Agent 根据当前会话上下文和可用原子工具决策。只有来源 ID、规范化选区或 UI 明确按钮这类可信结构化输入可以走极窄确定性直达。
- `research_message` 是用户可见会话的唯一事实源；`agent_turn/agent_run/agent_tool_call` 只保存运行、恢复和审计状态，不能再从旧运行记录反向双写一套消息。
- 进入论文助手时，会话列表按最近活动时间倒序选择第一项；只有该论文确实没有历史会话时才创建新会话。会话选择器和“新对话”是显式功能，不应在每次进入时强制打断用户。
- 论文研究页被路由缓存时，从文库再次进入同一论文不会触发论文 ID 变化；助手会话初始化必须绑定“进入研究页”这一生命周期，而不能只依赖组件首次挂载或论文 ID watcher，否则显式新对话状态会错误跨页面保留。
- 同一论文的不同 `conversationId` 只共享版本化来源和论文画像；近期消息、滚动摘要、指代焦点、选区和附件认领必须完全隔离。
- 通用知识不能写成论文事实，也不应进入论文长期记忆；论文推断必须保留证据与推断属性。
- 首次执行冻结版本化上下文和非密钥模型能力快照；等待恢复和安全重试只能复用同一会话、论文版本、Run 与可信附件身份。

## 检索与证据

- RAG 的事实边界是可回到当前 PDF 的 evidence，而不是向量分数或论文画像。
- 技术论文检索混合精确标识符、关键词、章节/类型和选区邻域；当前默认实现不依赖 Embedding 或向量服务。
- 中英文混合查询必须分离汉字、拉丁/数字和希腊字母 run，保留 SINR、RSMA、SIC 等技术标识符。
- 召回以当前问题为主。窄问题找到高相关直接证据后，不应为填满数量继续加入弱旁支；广泛问题则按章节覆盖。
- “最重要/最核心/最关键”等全文判断题不是一个可直接字面搜索的短语。应将其视为跨章节综合检索；涉及公式时，以 PDF 中带编号的公式区域为候选锚点，结合所属章节、正文引用次数与相邻解释段形成有界证据集，再由模型在这些候选内作出判断。
- 公式型判断题优先召回定理结果，证明中间式只能作为推导依据；若回答声称某公式是定理结论，Evidence Gate 必须检查来源关系，而不能只检查页码或公式编号存在。
- 明确依赖当前论文的问题不得在零召回时退化为通用知识回答；结构与词法召回均为空时，应在模型调用前返回稳定的无证据错误。普通无关问题仍允许零论文证据对话。
- 多路召回先融合排名，再按直接性、类型、位置、置信度和重复程度过滤；默认不增加一次 LLM 重排序。
- 同一原句、公式或图表的目标和支撑上下文应组成一个证据单元，避免重复页码和重复 claim。
- 只有本轮候选集内、分数有效且版本一致的 evidence ID 可以通过 Evidence Gate。
- 回答块应直接绑定稳定来源 ID；不能从独立 Markdown 和 claims 中用模糊相似度猜引用位置。
- 引用覆盖率只回答“已经写出的结论是否有证据”，不能证明回答完整。普通论文问答应把用户当前问题作为有界回答契约；每个回答块显式绑定要求 ID，门禁至少检查直接问题是否被处理。不要为拆分回答要求额外调用一次模型，以免增加延迟、Token 消耗和不必要的修复。
- 回答要求必须由当前问题与本轮 evidence 动态生成，不能为 SINR、SIC、公式等具体案例写固定规则；上下文要求只保留会显著改变直接答案含义的假设、范围或限制，避免把全部相邻内容强塞进回答。
- 不同模型可能对原文短引文做空格调整或轻微改写；服务端优先在模型已绑定的 evidence ID 内选取有词项重叠的精确原文。若供应商改写了 ID，只有当原文短引句在本轮候选集中唯一命中时才可回绑真实 ID；多义或无匹配时必须拒绝。
- 一个回答块提及的技术缩写、公式编号或数学标识，若存在于所引证据中，也必须由该块的原文引句覆盖；章节标题不参与此检查，避免把 `SYSTEM MODEL` 当成待引用事实。
- 模型若把回答块明确标为 `GENERAL_KNOWLEDGE/EVIDENCE_LIMIT` 却仍附论文引用，服务端应确定性删除这些引用；不得把非论文块强改为论文事实，也不得因此触发一次昂贵但无效的模型修复。
- `EVIDENCE_LIMIT` 是内部质量判断，不是面向用户的回答内容；前端应隐藏该类回答块，但不能删除后端门禁与运行记录中的诊断信息。
- `INFERENCE` 已是结构化事实类型，前端会统一显示“据此推断”；门禁不应再强迫模型在同一段自然语言中重复“推断/可能”等字样，否则会为纯展示措辞触发昂贵且易截断的修复调用。
- 用户上传到对话的附件属于本轮辅助上下文，不属于左侧论文证据：客户端只保留文本附件的轻量预览，PDF/Word/图片必须上传原始字节；后端校验会话、类型、大小、路径与哈希后由 Turn 原子认领，并交给文档解析 API。解析角色已验证原生 PDF 时直接发送 PDF，否则将 PDF 页面渲染为图片；Word 提取段落/表格和内嵌图片后以文本+图片发送。解析结果只作为有界不可信上下文，不生成论文 cite，也不把二进制正文写入运行记录；手动 LaTeX 公式保持原文直注入。
- 正文回链优先在指定页用 PDFium 查找服务端绑定的完整原句；唯一原句可覆盖可能过时的 block bbox，多义结果再用 bbox 选最近目标。不得用少量宽泛关键词冒充精确定位；失败后明确降级为段落框。
- 公式、图表和表格使用独立 target bbox；公式区域由编号/主体及同簇碎片的并集构成，支撑正文 bbox 不能冒充点击目标，单栏目标不能跨入邻栏。
- 引用的“支撑引文”和“点击定位目标”必须分开：定理文字可以证明公式结论，但公式角标只能跳到服务端版本化的公式区域框，不能再用证明文字搜索结果覆盖该框。
- 可信结构化白名单操作可在模型循环前执行，但参数必须引用服务端当前版本的 `SourceObject`；即使绕过模型也必须创建 ToolCall、ActionTicket 并等待客户端真实回执，不能直接宣称成功。

## 模型与供应商

- “OpenAI-compatible”只表示协议相近，不代表 URL、Token 参数、SSE、结构化输出、推理字段和图片能力相同。
- 供应商和接入通道由能力档案管理，Base URL 不可统一删除或追加 `/v1`；模型 ID 必须允许编辑。
- 可用模型查询只使用弹窗当前的 Base URL 与 API Key 临时访问兼容的 `/models` 端点；查询结果不代表保存设置，遮罩 Key 应回退到后端已保存密钥，错误响应不得回传密钥或上游正文。
- API 能力测试同样只使用弹窗当前的 URL、Model 和一次性 Key 草稿，不调用设置保存接口；空 Key 仅表示复用已保存密钥，测试通过的能力记录按草稿签名保存为诊断数据，草稿本身仍须点击“保存设置”才会生效。
- 结构化任务使用 JSON schema/response format，并拒绝空内容、截断内容和只有 reasoning 的响应。
- 结构化响应即使正文非空，只要供应商报告 `LENGTH/MAX_TOKEN` 或输出已触顶，也必须视为截断；首次调用不应预先扣除一整次恢复预算，但短问答应设置符合产品长度的输出上限，恢复调用再按供应商实际消耗计算剩余量，避免无界输出挤占修复空间。
- Evidence Gate 只允许同一证据集修复一次；日志只保存低敏摘要、Token、耗时和稳定错误码。
- 技术术语引用校验只要求回答中的论文事实术语能在短引文中对应；章节路径中的全大写标题属于定位元数据，不能反向要求每条事实短引文重复标题词，否则会把有效回答误判为无证据。
- 回答要求由服务端从用户当前问题直接生成，不消耗模型调用；证据门禁修复复用同一要求并优先携带已引用证据，不能在修复时重新规划或随机缩小回答范围。关键上下文是否充分由回答提示和证据质量约束，不用第二个规划模型强行枚举。
- 异步任务只有在尚未进入 Evidence Gate 修复时才能安全重放模型步骤；修复依赖内存中的上一版回答，修复开始后的供应商故障必须保留原错误并终止，不能丢失前驱答案后仍沿用一次性修复计数。
- 证据门禁修复不应重放首轮完整 Prompt；只携带当前问题、失败原因、精简旧答案和已引用/高优先级证据，否则简单问答会在修复前因总 Token 预算自我拒绝。
- 强推理模型的隐藏 reasoning 会消耗 completion token；只有供应商明确支持且实测有效时才发送专有推理参数。
- 论文分块摘要、全局画像、JSON 修复和公式转写属于有界结构化抽取，不依赖深度推理；对 Kimi 使用低推理策略应映射为关闭 thinking。分块失败后不得用完全相同的输入和预算自动重放，成功分块应保留并只在用户重试时处理失败分块。
- 聊天模型不能自动充当 Embedding 模型；当前论文问答和兼容 Skill 都不得暗中增加 Embedding 或 LLM 重排调用。
- 对话角色和文档解析角色仍可在设置页执行能力探测；文档解析角色必须通过图片探测，原生 PDF 只在固定小 PDF 探测成功时启用。URL、Key 或模型改变会使旧能力签名失效，瞬时错误不能永久降级。能力记录用于诊断和界面提示，不作为每轮 Agent 的硬门禁。
- 文档解析角色使用 Kimi Coding 时也必须发送 `thinking={"type":"disabled"}`：整篇论文理解是有界的结构化抽取，不需要隐藏推理；漏发该参数会让多图整篇请求消耗完整 180 秒客户端截止时间，而单图能力探测仍可能正常。修正后 184、185、190 三篇真实论文的整篇请求分别约 93/53/69 秒完成。
- Agent Runtime 通过 LangChain4j AI Services 使用原生 Tool Calling，但不强制每轮调用工具：`ToolChoice.AUTO` 允许与当前论文无关的问题、无关选区问题直接得到一次普通回答；需要论文事实时模型按需调用读取 Skill，并用 `submit_answer` 绑定已读来源。运行时以模型实际响应、结构化提交和论文来源校验为准，能力探测失败不能阻断普通直答；明确依赖论文但未提交可验证来源的回答仍会被拒绝落库。
- Skill 只表示可按需启用的重复能力包（例如论文读取、明确页面操作）及其原子工具，不是关键词路由器、固定 Workflow 或答案生成器；页面操作工具仅在用户明确提出操作时开放，目标不清晰仍由 Agent 自然语言追问。
- `paper_overview` / `paper_evidence` / `page_action` 应作为三个独立 Skill 由 Agent 自主选择，不使用关键词路由预先焊死流程。页面操作的安全性由确定性边界保证：只接受当前选区或本轮已读来源，只允许白名单操作，参数/版本/权限必须校验，歧义时由外层 Agent 自然语言追问；Skill 内不再调用第二个 LLM 理解指令。
- LangChain4j `TokenWindowChatMemory` 不能被依次塞入多条不同的 SystemMessage；新的系统消息会替换旧消息。基础规则、会话摘要状态和 Skill 说明必须在调用模型前合并成唯一 SystemMessage。
- 当前论文打开只注入轻量状态（论文 ID、原文和画像是否可用），不注入全量画像或正文。普通问题直接回答；整体论文问题按需读画像；精确事实、公式、页码和引用再按需批量读原文。
- 论文画像的 `READY` 不能只表示模型调用和 JSON 解析完成。至少还需要确定性校验论文/版本身份、核心字段、分块覆盖和 claim 证据 block ID。未达标但身份可信的画像作为 `PARTIAL` 按需使用，精确细节仍通过原文证据核验。
- 乐观锁实体完成状态迁移后，后续同一链路必须使用迁移方法返回的新版本。ActionTicket 若继续使用注册工具时的旧版本，会稳定地更新 0 行，并诱发模型无意义重试直至预算耗尽。
- API 设置的用户输入只包含 URL、API Key 和 Model，不要求用户理解供应商或通道枚举。对话角色使用 OpenAI-compatible 协议；文档角色根据 URL 自动识别 Gemini Native 或 OpenAI-compatible。模型目录查询必须按角色使用对应密钥，并兼容 OpenAI `data[].id` 与 Gemini `models[].name`。

## 前端交互

- 当供应商不再是显式配置项时，模型字段必须保持自由文本输入；模型目录查询只提供下方候选标签，不能把查询结果重新变成带预置含义的下拉选择器。
- Agent 的完成与归档必须由服务端拥有：页面只负责提交统一 Turn、观察状态和执行 ActionTicket；卸载组件不得以浏览器内存作为真相，刷新后由 `runId` 与 `research_message` 恢复。
- Agent Turn 的 HTTP 提交必须在轮次与运行记录持久化后立即返回，耗时模型循环由服务端专用线程池执行；不能以延长浏览器超时模拟后台运行。前端离开页面只能终止本地轮询，重新进入时应从用户消息保存的 `runId` 恢复观察。
- 恢复后台运行时只能检查会话最后一条消息：只有最后一条是带 `runId` 的用户消息才可能尚未归档。向前扫描任意没有配对助手消息的历史用户轮次，会把早已失败的 run 误显示成当前仍在处理。
- 自动恢复还必须按 `runId` 去重并区分终态与连接中断：`FAILED/CANCELLED` 查询一次后停止观察，不能在 `running` 结束时再次刷新历史并递归恢复同一 Run；网络错误或页面主动停止观察则应释放去重标记，允许之后重新连接。
- Agent 错误提示属于产生该 Run 的研究会话，不能使用跨会话的全局错误 ref 直接渲染。切换或新建对话时按 `researchSessionId` 读取/清空显示状态，切回失败对话时仍可查看原错误。
- Agent 的模型—工具循环应交给 LangChain4j AI Services：框架负责原生 Tool Calling、参数解析、工具结果回灌和轮次终止，项目 Runtime 只负责持久状态、幂等、权限、证据校验与后台任务。上下文用 TokenWindow 限制，工具结果单独限量，循环用最大 tool round trips 限制；框架返回的实际 Token 用量用于观测和持久化，不应在答案已经生成后再用累计预算门禁把成功轮次改判失败。
- 最大 tool round trips 只是最终保险，不能作为常规停止策略。论文发现阶段使用 `retrieve_paper_evidence` 将多个检索意图、候选合并、去重和原文读取放在一次工具执行中；等价的只读参数在同一轮运行中复用结果，Agent 仍可根据新缺口自主发起后续批量调用。数据大小和单次检索意图数量边界只用于防止异常载荷，不能代替证据判断或强迫提前提交。
- 消息上下文标签只能展示已经确定的事实：有选区才显示选区，有真实引用才展示论文依据；不能因为对话挂在某篇论文下，就把普通问题标成“基于论文理解”。
- 对话滚动属于局部消息容器状态。只有内容确实可滚动且用户离开底部时才显示“回到最新消息”按钮；新消息自动滚动与用户主动回到底部应复用同一个定位函数。

- PDF 对象使用 `shallowRef`，避免 Vue 深度代理破坏 PDF.js 私有字段。
- 虚拟页的渲染状态必须绑定当前 DOM 和 generation；KeepAlive 激活后等待非零布局并重绘可见页。
- SVG 标注层默认不截获文字选择，只有已有标记、拖柄、笔记/批注图标或公式模式接管指针事件。
- 笔记和批注都绑定原文，拖动只改变图标位置；批注仅在列表打开时展示。
- 新拖选只形成候选；确认后作为下一条消息附件，任务被后端接受后自动卸下。切换候选、附件发送或取消选区都不能清空对话。
- 模型回答统一由安全 Markdown/KaTeX 渲染，关闭原始 HTML 和 KaTeX trust，不显示思考过程。Agent 回答块的 `text` 必须是完整 Markdown：标题使用 `##/###`、重点使用 `**粗体**`，数学使用 `$...$` 或 `$$...$$`；引用清洗必须保护数学环境和 `[0,1]` 等区间，不能用全局数字方括号正则破坏公式。
- 公式框选区域可能同时包含多条独立公式；视觉协议必须返回按从上到下、从左到右排序的公式数组。一个选区作为公式组持久化、逐条编辑和展示，再以组合 LaTeX 形成同一个可定位上下文锚点；旧单公式记录继续按单元素组读取。
- 已确认的公式选区属于待发送上下文，不是 PDF 点击态。普通点击、切换工具或切换选取模式不能静默清除；只有右侧关闭可以直接移除，新的文字或公式选区必须在完成拖选后询问是否覆盖，取消时恢复原固定内容。
- 论文对话输入遵循常见即时通讯习惯：Enter 直接发送，Shift+Enter 插入换行；输入法仍在组合文字时的 Enter 不得触发发送。
- 论文助手顶部应保留内容/公式选择方式与对比文献入口；文字确认后可折叠为紧凑摘要。公式的“固定内容”只负责识别并展示可编辑 LaTeX，不收起；首次“确认固定”和后续“保存校正”均只在保存成功后折叠，并允许重新展开。
- 对话中手动输入的 LaTeX 应作为可编辑的独立公式标签，而不是把 `$$...$$` 直接写进问题正文；标签按“公式1、公式2……”命名，与文件附件共同受每轮最多 3 项的限制，并作为辅助上下文而非论文 cite 发送。
- 无选区不等于无论文上下文。Agent 先依据问题、对话、可信选区和论文画像形成回答，再按需读取原文获取佐证；证据是增强项而非回答门禁。读取失败或没有命中时仍可基于已有有效上下文回答，但不得伪造引用、页码、公式编号和精确实验数值。
- 同一对话的有界历史应始终保留，但无关问题不能继承旧证据焦点。后端用统一关系分类区分 `INDEPENDENT / FOLLOW_UP`，前者只按当前问题检索，后者可以用最近问题扩展检索并优先复核上一轮证据。前端“沿用对话上下文”以后端实际路由结果为准。
- 回答内角标与展开后的证据列表必须共用一份“逻辑来源”序列；同一公式的可读文本负责展示，区域证据负责跳转，两者合并成一个编号，不能重复显示页码按钮。
- Agent 返回给前端的每条证据必须同时携带 `paperId` 和来源定位器；前端据此区分当前论文与跨论文来源。兼容重构前已保存的消息时，缺少 `paperId` 的证据只可在当前论文工作台中按当前论文处理，不能因 `undefined/NaN` 比较直接拒绝跳转。
- 模型不得在回答正文自行书写 `[1]` 等证据编号；编号由通过服务端回绑的 citation 顺序唯一生成。Prompt 约束之外，论文回答在持久化前应清理模型数字标记，前端对历史消息也应防御性清理，避免不可点击的模型编号与系统可点击编号并存。
- 同一回答块中同页同基础编号的连续子公式（如 `(35a)–(35g)`）只在展示层合并为一个复合证据；底层 `SourceObject` 仍保持原子，点击复合证据时传递 `formulaNumbers` 列表，让 PDF 查看器逐个高亮编号。
- `submit_answer` 只负责把需要引用的 `answerBlocks` 与本轮已读取的 `sourceObjectIds` 绑定为可点击证据；无需引用或证据不可用时，模型可直接返回 Markdown。服务端只校验模型实际提交的引用，不以是否提交证据决定回答能否显示。
- 文本来源不能只按 evidence ID 去重：同一版面 block 内的不同精确引句是不同来源；相邻 block 中阅读顺序连续、同栏、几何相邻且前句未结束的引句应合并为一个跨行逻辑来源。
- 跨行逻辑来源对用户显示空格归一化后的完整句子，但给 PDFium 保留分片目标文本；搜索分别定位每个物理行片段后合并字符框，避免依赖跨行字符串是否能一次命中。
- 模型在回答中的引用顺序不等于 PDF 阅读顺序。跨行证据应先按论文、页码、readingOrder 和几何位置重建物理顺序并合并，最终来源编号也按 PDF 物理顺序确定；公式引用插在两个文本片段之间时不能阻断原句合并。
- 正文多行或跨行来源的联合 bbox 只用于粗定位，前端高亮必须优先使用 `targetBoxes` 中的物理行框，不能画一个覆盖栏间空白或隔壁栏的大矩形。公式证据不再尝试框住完整公式：后端透传公式编号，前端在目标页搜索并高亮 `(21)`、`(1b)` 等编号后滚动到该处；坐标只作找不到编号时的滚动兜底，不绘制误导性的大公式框。一个证据代表多个子公式时可携带编号列表并同时高亮，编号缺失则只做近似跳页提示。
- 定理、引理等结论若在回答中明确声称对应某个公式编号，Evidence Gate 除校验 citation ID 与引句外，还必须校验公式来源的 statement relation 和 equation number；证明步骤或其他编号不能冒充结论。
- 对话与论文阅读意图由同一个 Agent 基于当前问题和上下文判断，不新增预分类模型或固定工作流。服务端只保留可靠性边界：引用必须来自本轮可信来源，页面修改必须使用白名单工具，歧义操作必须先追问。
- 可执行科研命令必须由服务端白名单解析；前端只执行声明过的高亮、下划线、笔记、批注或跳转动作。选区命令直接绑定规范化字符框；全文命令先召回正文语义锚点，再在同页、同阅读流绑定最近公式区域。模型不得生成坐标，普通正文定位失败时不得落库。
- 操作白名单应覆盖“找出/定位 XX 并高亮/下划线/批注/笔记/跳转”和“将 XX（对应区域）执行操作”等直接表达；解析后清理操作性后缀，并把备注正文作为独立字段传递，不能让自由模型文本直接控制 PDF。
- 操作命令必须在上下文继承和检索之前解析。带明确目标的操作无条件隔离旧问题、旧 evidence 焦点和旧回答；“把它/该公式高亮”等指代操作才继承上一轮。执行结果可包含多个受证据约束的目标，例如同一概念对应的多条公式，但必须限量并由服务端白名单动作落库。
- “这段文字/当前选区”不是待检索关键词。存在本轮规范化选区时，这类高亮命令应直接绑定选区字符锚点和已解析的 selected evidence，以确定性路径执行，不依赖模型重新猜测引用对象。
- 证据跳转应在目标页渲染完成后，依据已挂载页面的真实偏移和目标归一化坐标同时调整纵向/横向滚动，不能只跳到页首。
- PDFium 选择层没有浏览器原生 Selection；复制功能必须在 `copy` 事件或右键菜单中把当前可读选区显式写入系统剪贴板，同时不得覆盖输入框自己的复制行为。
- PDF/助手只持久化宽度比例；页面不足时允许 PDF 横向滚动，不能裁掉论文内容。

## 安全、运维与验证

- 配置读取只返回脱敏值；生产缺少 `RA_MASTER_KEY` 时 fail-closed；CORS 禁止通配符。
- 文件路径必须限制在配置目录内；MySQL 与 PDF 分开备份。
- 本地论文统一存放在项目根目录 `data/papers`，数据库继续保存相对文件名。打开文献目录的接口不接受客户端路径，只能打开服务端已配置的存储根目录。
- 论文文件与数据库不能做为两条互不相关的删除链。应先在事务内删除论文及其级联数据，再在 `afterCommit` 删除 PDF 与派生资产；所有路径必须规范化并校验仍在配置根目录内，避免数据库回滚后文件已丢失或路径越界。
- health、metrics 和日志只记录低基数低敏信息，不记录密钥、论文正文、Prompt 或 Provider 响应体。
- 本地服务就绪以 3306 监听、后端 health 和前端 HTTP 响应为准，不能只相信 PID。
- 本地启停脚本只能终止其 PID 文件可追溯且进程树属于当前项目的进程；目标端口被未知进程占用时应拒绝误杀。数据库优先使用管理命令优雅关闭，超时后才终止已确认归属的进程树。
- MyBatis Plus 默认不会把实体的 `null` 字段写回数据库；承担可恢复状态机的输入、输出、错误和时间字段必须显式允许 `NULL` 更新，否则重试只会在内存中看似清空。
- 常规验证顺序为后端 `clean test`、前端单测和生产构建；PDF 变更还需真实双栏/数学论文浏览器验收。

## 整篇论文理解（2026-08-27）

- 论文理解的语义调用必须是单次整篇请求；页面与 block 划分只能作为传输顺序和来源定位标记，不能再被当作模型理解边界。
- 解析角色已验证图片能力后，非原生 PDF 模型接收按页结构化文本和全部页面图片；原生 PDF 模型同时接收原生文件和结构化来源文本，以保证理解与 block 来源能够统一回绑。
- 首版不实现长文分治、识别失败回退、模型 JSON 修复或第二评价模型。若三篇数据库论文测试暴露上下文或视觉限制，只根据实际错误增加最小改动。
- 论文理解版本变化必须使旧 `profile_json` 失效；现有 `paper_memory` 表可继续承载新的整篇理解结果，避免在效果尚未验证前扩大数据库迁移范围。
- 非原生 PDF 的页面图片仅用于补足公式、图表和版面视觉信息，当前按 72 DPI 发送并保留结构化正文作为主输入；最多 40 页、64 MB，避免图片输入无界增长。解析角色的 LangChain4j 模型关闭自动重试，单次整篇请求超时即记录失败，不再在后台悄悄重复发送同一份大请求。
- 整篇画像写入旧的分类字段时只能使用枚举值（如 `THEORETICAL`），不能把模型生成的 domain 等自由文本拼接进去；自由文本应留在画像 JSON，避免数据库字段截断并阻断理解任务完成。

## 语义 span 与页面操作（2026-08-28）

- 原始 PDF block 是坐标事实，不应为改善模型阅读而改写或覆盖；在其上确定性生成同页语义 span，既能减少碎片，又能通过 `sourceBlockIds` 无损回到页码和 bbox。
- 整篇理解模型应引用 span ID，服务端入库时展开为原始 block ID。这样画像继续兼容现有数据结构，证据与页面操作也不需要第二套定位系统或新数据库表。
- span 合并必须保守：同页、同栏、同章节、几何相邻只是基础条件；明显小节标题、列表项、完整长句后的新句首和 `Fig. X exhibits...` 等新段落信号应切断合并，并设置块数/字符数上限以防整节过度合并。
- 角色纠正只覆盖可确定的误判：无结构化 LaTeX、数学特征不丰富且具有自然语言形态的 FORMULA 可按 BODY 读取；正文中的图号引用句不能当作图注。原始角色仍保留以便审计。
- 图注应保留在整篇输入和来源目录中帮助模型理解图表，但不应拥有论文画像的可引用 span ID。真实失败样本表明，仅靠提示禁止模型把图注当作性能结论证据并不稳定；在输入层标记为无证据 ID 更轻量、确定，且不影响后续加载图注或页面操作。
- 页面操作不得让模型生成坐标。Agent 只选择来源对象，Skill 从 span 的 block locators 确定性生成一个或多个矩形；当前单页 span 与既有 ActionTarget 契约兼容。
- 画像质量报告是离线/观测信息。生产状态只以一次调用是否成功解析并持久化为 READY/FAILED，不因贡献、发现等可选字段缺少而引入 PARTIAL 门禁。

## 轻量证据获取（2026-08-28）

- 当前四篇真实论文已证明：语义 span 上的确定性词法检索足以支持证据获取，12 个检查点 Recall@4 为 100%、MRR 为 1.000。在出现可复现召回失败前，不应引入向量库、重排器、查询改写模型或第二证据判断模型。
- 模型需要看到的是少量原文、来源角色、页码、章节与公式号；候选总数、内部覆盖率、文档版本、坐标和画像质量报告属于服务端诊断信息。把这些字段放入工具结果会增加上下文并可能诱发无意义的重复检索。
- `paper_overview` 用于低成本建立全局理解，但不直接产生引用；`paper_evidence` 用于原文核实和可点击引用；`page_action` 只执行用户明确要求的页面修改或即时跳转。可点击引用本身不是页面操作，应由带来源 ID 的最终回答生成。
- 图注可以作为检索和理解的辅助来源，但性能、数值和对比结论应优先引用正文、表格或公式。这个规则适合作为 Skill 使用提示，不需要新增一套证据门禁。
- 证据评测应分两层：确定性层检查 Recall@K、MRR、直接支撑和 locator 有效性；真实 Agent 层检查是否主动取证、引用是否对应答案、无依据时是否拒绝伪造、证据调用次数和是否误触页面操作。评测失败必须先排除真值页码、措辞和“必须调用工具”等测试假设错误。
- 单次真实 Agent 通过不能证明工具调用已经收敛。同一类问题可在不同运行中执行 1 次或 4 次证据检索；必须保留曾触发上限的样本并重复运行，分别统计答案通过率、证据调用次数和 `TOOL_ROUND_LIMIT`。不能用更容易的问题替换失败样本后宣布完成。
- 对当前三 Skill 架构，证据读取应是“每轮一个批次”，而不是让模型用多次工具往返逐步试探：Agent 在一次参数中提交多个证据需求，Skill 内部逐项检索并返回覆盖状态。模型后续即使再次请求，也只应复用首批结果，不再次执行搜索。
- 工具轮次上限只能是内部保险，不能成为用户可见失败。达到保险线时，可在现有模型适配层切换到只允许最终提交的收尾调用；这比提高上限或增加外部编排服务更轻。该收尾必须只使用本轮已加载上下文，不得生成新证据。
- 模型生成的检索参数必须容错：对超长 query 和超量数组安全截断，对未知可选过滤忽略并继续。参数 schema 用于引导模型，服务端边界用于保证一条异常参数不会浪费整轮回答。
- 证据链路验收不能只统计“有没有调用工具”。至少应同时记录真实检索次数（排除缓存复用）、工具与端到端耗时、每个 evidence need 的 found 状态、响应字节数、最终提交来源是否为首批返回子集，以及原文是否直接支撑核心结论。
- 论文画像中的 claim 已在解析阶段绑定原始 block。跨语言或模型生成的长查询召回不稳时，应优先复用这条既有绑定：画像只给 Agent 轻量 `claimRef`，证据 Skill 在服务端解析到当前版本来源；查询未携带 ref 时可用短前缀与画像 finding 做轻量匹配。无需再增加向量库、重排器或第二模型。
- 本地证据 Skill 与供应商响应必须分开计时。本地检索快不代表端到端可用；交互运行仍需独立 wall-clock 预算，超时后返回明确安全失败，不能让后台迟到回答覆盖终态或把未完成证据交给用户。

## Agent 首轮延迟定位（2026-08-29）

- 普通短问在相同模型服务和论文会话下约 1 秒完成，而论文证据请求的本地检索约 0.2 秒、端到端约 8–18 秒；因此排查首发模型超时应先看 Agent 的模型轮次数、工具往返和输出长度，不能把本地 Skill 耗时当成模型服务延迟。
- 论文事实问题通常可以先用一次批量证据调用，再直接回答；但这只是高效建议，不是工作流门禁。证据结果返回后由 Agent 判断是否足够，新的、未解决的需求仍可再次读取，完全相同的请求才适合通过缓存减少重复 IO。
- 画像 claim 的确定性绑定应优先复用；当中英文术语或同义中文表达导致简单字符匹配分数偏低时，先做极小的领域术语归一化，再考虑更重的检索组件。当前真实样本已通过该方式解决短码长/BLER 的错误 claim 绑定，无需引入向量库或二次模型。

## Agent 上下文与 Skill 自主决策（2026-08-29）

- Skill 是否调用、调用顺序和是否再次调用属于 Agent 决策；后端只按当前论文来源是否可用暴露能力，不根据“画像是否已加载”或“证据是否已完成”隐藏 Skill。
- 当前运行内的工具结果由 LangChain4j 记忆自动回灌；跨回合由 Runtime 持久化的只读工具结果恢复为带边界的普通参考消息。恢复内容不是 Tool transcript，避免把某个供应商的调用协议写死到上下文层。
- 恢复只接受当前会话且匹配当前论文 `documentHash/parserVersion` 的已完成只读读取；来源 ID还要存在于当前来源目录，才可用于引用或页面操作。这样上下文可复用，但不会跨论文版本污染证据。
- 运行时使用 110k 的宽 TokenWindow 预算和通用模型/工具/时间保险；达到保险线只触发安全收尾，不承担论文语义流程。上下文超预算时优先淘汰较早的普通参考消息，Agent 发现信息不足时再按需调用相应 Skill。
- 完全相同的只读请求可以做进程内缓存以减少无意义 IO，但缓存不是“本轮已完成”的业务状态；不同查询仍然可以执行，不能把缓存结果改写成禁止继续检索的回复。

## 证据链路运行时安全与性能（2026-08-29）

- 真实复测确认证据 Skill 本地检索不是延迟主因：四篇论文 6 个请求的单次证据调用最大耗时 298ms；端到端耗时主要由模型往返次数和模型收尾响应决定。
- 对单次 Agent 运行保留 2 轮通用能力调用保险，足以覆盖一次批量证据读取或一次聚焦补查；这不是画像→证据的固定顺序，Agent 仍可按上下文选择能力，工具一次仍可提交多个证据需求。
- 当前模型适配器单次请求最多等待 60 秒，因此持久化运行 deadline 设为 70 秒；deadline 只是最终安全边界，正常调用由工具轮次保险限制，避免通过无限提高等待时间掩盖重复调用。
- 终态转换必须在可见助手消息写入前成功完成。超时线程先完成时，迟到模型结果不得再落库或覆盖失败状态；超时扫描只处理仍为 `RUNNING` 的有效候选，并安全忽略并发终态。
- 最终完整 10 例无 `FAILED` 或 `RUN_TIMEOUT`，P50/P95 为 26.2/36.3 秒；四篇论文的 6 个证据请求均正常结束。严格内容未通过的样本应继续按证据充分性、回答词面和页面操作意图分别分析，不能再归因于工具调用超时。

## Agent 化 Skill 契约与轮次复测结论（2026-08-29）

- Agent 需要自主决定是否调用、调用顺序和是否再次调用；应用层不应把画像→证据、一次证据后必须回答或固定工具轮次实现成语义工作流。运行时的数量字段可以保留作观测，但不能据此隐藏 Skill 或强制终止正常的不同需求。
- “一次证据调用支持多轮检索”应落在 Skill 内部：模型一次提交多个 `needs`，Skill 对每个需求执行主检索，未命中时只做一次有边界的 fallback，然后返回每个需求的覆盖状态。这个边界控制的是一次工具 payload 内的搜索，不是 Agent 跨回合次数。
- 本轮真实复测说明 Skill 本身已能稳定返回：四篇论文 6 例证据工具无失败，本地调用最大约 131ms；但模型仍可能在 `coverage=complete` 后重复提交相同或近似 `needs`，论文 190 的一个问题达到 9 次检索。不能把“证据召回正确”误认为“Agent 已收敛”，后续应单独优化描述、结果可读性和模型行为，并保留困难样本。
- 页面操作 Skill 当前故意保持单动作票据，因为现有客户端回执、幂等键和标注写入都是单工具调用合同；只有真实需求证明批量操作有价值时，才单独设计批协议，不为临时测试扩展状态机。
- 110k TokenWindow、当前会话历史恢复和工具结果回灌继续由上下文/runtime 提供支撑；90 秒只是 Kimi 60 秒单次请求之上的最终安全边界。迟到结果必须先检查持久化终态，不能覆盖失败或超时。

## Skill 描述不能单独保证 Agent 收敛（2026-08-30）

- 将证据 Skill 的名称、描述、schema 和结果状态写得更明确，能够改善模型参数表达和确定性检索接口，但不能假设模型一定遵守“同一需求不要重试”。Kimi 实测会在逐需求均为 `FOUND` 后重复完全相同的请求，单例达到 21 次证据调用并触发 90 秒终态。
- 进程内相同参数缓存只降低本地检索成本，无法减少 Agent 的模型轮次；重复调用后期虽然只有 2–4ms，端到端仍由反复模型生成主导。因此不能用 Skill 执行耗时或缓存命中掩盖 Agent 不收敛。
- 纯描述方案、硬运行时门禁和 Skill 内自包含完成信号是三个不同层次。真实轨迹已经否定“描述足够完善即可稳定停止”的假设；下一步若继续保持 Agent 自主性，应优先验证更明确、可机器读取但不依赖跨调用状态的完成语义，而不是重新加入论文专用 Runtime 工作流。
- `FOUND` 也不能只表示某个候选超过词面阈值。若返回正文事实之外的弱公式或错误画像 claim，Agent 会持续改写问题寻找更好的支持。候选资格与停止语义必须分别评估：前者看直接证据质量，后者看外层调用次数和端到端完成率。

## 证据覆盖与无进展停止（2026-08-29）

- 证据工具的 `complete` 不能表示“每个 need 返回过来源”；对于公式号、图表号、指标等明确目标，应返回 `coveredTargets`/`unresolvedTargets`，只有目标全部覆盖才算 complete。无明确目标的开放查询使用 found/partial 语义，避免给 Agent 虚假的完成信号。
- 重复检索的轻量判定应比较当前结果的 sourceObjectId 与 Agent 已可用来源集合。不同查询文本但没有新增来源时，返回 `newSourceCount=0`、`exhausted=true`，Agent 应立即停止；这保留了新需求继续检索的自由，也不需要查询状态表或语义去重模型。
- 论文证据被读取后，最终回答必须通过结构化提交绑定实际来源；普通 Markdown 只适用于未依赖论文或未获得可用论文来源的回答。该约束是输出协议，不是预先判断所有问题的固定工作流。

## 公式族与模型证据审计（2026-08-29）

- 复合公式应保留每个子公式的原子来源与 locator，但检索候选可按结构化公式号临时扩展同基号兄弟。论文 190 的真实 P0 案例证明，这种做法能在一次证据返回中取齐 `35a–35g`，无需新建复合证据存储。
- 在证据 Skill 内加一次通用模型审计并不自动意味更快或更收敛。当审计模型倾向保守地返回 partial/retryQuery 时，Agent 会把它解读为继续调用的理由；本轮真实案例中单次 Skill 因此增加数秒，复杂问题仍重复检索并超时。
- 审计层的验收必须同时比较“无审计基线”的总延迟、外层 Skill 调用数和最终直接证据质量。只证明模型能输出合法 JSON 或能选中来源，不足以保留该层。若无法显著降低外层调用数，应优先撤回模型审计，保留已验证有效的结构候选扩展。
- 当前生产链路已按这一结论撤回内部模型审计，仅保留公式族结构扩展。语义充分性继续由已获得原文候选的外层 Agent 判断，Skill 只返回可确定计算的来源、目标覆盖和无新增来源状态。

## Autonomous Driving 论文扩展证据评测（2026-08-29）

- 论文 190 的 15 条真实 Agent 案例覆盖直接事实、公式、复合公式和无依据问题。第二轮全部完成，端到端延迟 P50/P95 为 42.4/70.6 秒，真实证据检索 57 次；证据工具没有失败，说明本地检索不是本轮超时主因。
- 诊断必须区分三件事：第一批来源中没有用户所问事实、第一批查询没有召回已有事实、以及第一批已经足够但 Agent 仍继续搜索。按这一标准，本轮分别为 1 条预期源文不存在、4 条首轮召回不足、9 条首轮已足仍重复、1 条正常一次停止。ImageNet 负例在整篇解析产物中没有对应文本，且 Agent 正确拒绝编造，不能算解析缺陷。
- `coverage=partial` 不能直接等同于“证据不足”。多个首轮结果已包含直接可用的公式或正文，但模型生成的 needs 混入更宽泛的目标、OCR 乱码或与用户问题无关的目标，导致状态仍为 partial 并诱发后续搜索；公式 (35a)–(35g) 首轮已全部返回仍检索 7 次，是最明确的收敛问题样本。
- 本轮只扩展测试夹具并修正夹具 ID 长度问题，没有根据统计结果修改 Skill、Agent 或运行时；后续方案讨论应继续保留这 15 条样本及其调用轨迹，避免只用“回答通过”掩盖重复检索。

## 稳定基线与无进展保护回归（2026-08-30）

- 实验性证据契约将 `query/keywords/targets` 改为 `question/anchors` 后，真实 Kimi 运行出现大量重复相同请求；这说明契约简化不能以丢失已验证的检索输入和确定性状态为代价。当前回归恢复原有批量 needs、画像 claim 绑定、逐需求 fallback 和公式族扩展。
- 无进展保护采用最小实现：在当前 Agent 运行已有来源集合上比较本次返回的 `sourceObjectId`，将是否复用、获得多少新来源及 `noProgress/exhausted/stopReason` 返回给模型。它是可解释的 liveness 信号，不是固定工具次数、论文专用状态机或 Runtime 门禁；不同需求仍能正常发起新检索。
- 进程内缓存只能减少相同请求的本地检索，不会自动减少模型往返；因此验收必须同时看模型工具调用次数、实际证据检索次数、端到端耗时和最终引用质量。无进展信号是否被模型稳定遵守，需要真实 API 在解除限流后重复验证，不能仅凭单测推断。
- 本次全量后端回归为 527 项执行、0 失败、0 错误、9 跳过。15 条真实批测被 Kimi 组织级 `max RPM: 3` 限流污染；唯一可归因的隔离样本为 1/1、一次证据检索、约 50.5 秒。因此下一步应先在相同模型和相同数据上恢复可用 API 配额，再做对照测试，暂不继续堆叠保护逻辑。

## Agent Harness 与业务能力边界（2026-08-30）

- `/api/agent/**` 只承载对话 Agent 的 turn、附件和页面动作协议；检索、导入整理和论文理解任务使用各自的应用服务与路由。退役能力不保留空控制器、任务类型或兼容 DTO。
- 论文理解是生成稳定解析产物的应用任务，不是运行期按需触发的 Agent Skill。运行期 Skill 只暴露画像读取、证据读取和页面操作能力。
- 长对话上下文采用“滚动摘要 + 摘要边界后的原始消息”。摘要应在本地确定性完成并保留最近消息原文，避免为了上下文维护增加模型调用、延迟和限流风险。
- Harness 的模型观测只记录调用序号、耗时、消息与工具规模、Token、结束原因和错误类型，不保存提示正文、回答正文或私有推理；观测失败不得改变 Agent 的业务结果。
- 工具错误的 `retryable` 必须基于故障性质：超时、限流、过载和网络连接异常可重试，参数校验、证据校验和业务状态错误默认不可重试。该语义用于帮助模型决策，不演变成固定工具轮次工作流。

## 标准 Agent Skills 渐进式披露（2026-09-06）

- Skill 的最小可移植单元是独立目录中的 `SKILL.md`，frontmatter 提供 `name` 和 `description`，正文提供激活后的完整说明；`scripts/`、`references/` 和 `assets/` 都是可选项，不应为了形式强行创建。
- LangChain4j 官方 Skills 负责发现元数据、`activate_skill` 和激活后的资源/工具披露。应用只负责把既有 Java 能力绑定到相应 Skill，不在 Runtime 中按用户问题分类、隐藏 Skill 或规定画像→证据的固定顺序。
- 论文画像、证据/局部视觉和页面操作分别是三个能力边界：画像结果与证据结果进入当前模型记忆，后续由 Agent 复用；跨回合只恢复当前会话、当前论文版本的有效上下文和官方激活 transcript，缺失时再由 Agent 激活。
- 视觉图片只在证据 Skill 明确返回且下一次模型请求确实需要时传递，避免默认把所有页面快照塞入上下文；工具结果仍保存可信来源 ID，页面操作只接受这些 ID。
