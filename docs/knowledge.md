# 知识总结

> 只记录稳定、可复用的设计结论；日期、测试数字和完整变更由 `progress.md` 与 Git 保存。

## 工程与数据

- 本地单机优先，不为形式引入微服务、Redis、图数据库或第二套状态系统。
- Controller 管协议，Service 管业务，Mapper/Entity 管持久化；长任务返回 `taskId`。
- Flyway 目录是唯一数据库结构真源；删除已发布领域对象只能新增迁移，不能改写历史迁移。
- 测试使用独立 H2；旧库升级前先备份和核验，禁止对未知 schema 盲目 baseline。
- 删除 Java 类后的最终验证必须执行 `mvn clean test`，避免 `target` 残留 class 造成假通过。
- 研究会话、workbench run 和异步任务是不同生命周期：会话恢复用户对话，run 审计单轮执行，任务表达后台状态。
- 源码、配置和文档统一使用 UTF-8；PowerShell 读取中文文件显式指定 `-Encoding utf8`。

## PDF 事实层

- PDF.js 只负责 canvas 渲染；PDFium 统一负责字符命中、字符范围、选择矩形和全文搜索，禁止再从 TextLayer DOM 推断阅读顺序或分栏。
- 浏览器锚点由 `PDF fingerprint + page + charStart/charEnd + normalized rects` 标识，缩放不改变字符范围和归一化坐标。
- PDFBox 负责服务端版面 block、角色、阅读顺序和几何；外部解析器只可显式启用并经过质量比较，默认部署不依赖 GROBID、MinerU、Marker 或云解析。
- 版面角色与内容精度分开：`TEXT` 可引用原文，`STRUCTURED` 可提供可信结构，`REGION` 只能证明页面区域。
- 文本能否精确映射与能否支撑论文事实是两个维度；参考文献可精确选择，但其证据用途仍可受限。
- 原文匹配先做 Unicode NFKC、连字、软连字符和空白归一化，同时保留回原始 UTF-16 偏移的映射。
- 数学密集正文不是扫描件。先复用 PDF 字符事实，再提供 `READY / APPROXIMATE / UNAVAILABLE` 的 LaTeX 辅助；近似 LaTeX 不能替代原文。
- 公式精确框选是默认选择不足时的后手。图像转 LaTeX 只在用户点击固定后按需执行，候选必须确认后才能成为证据。
- 公式视觉输入优先复用已确认缓存和版面结构；客户端裁图不可信，服务端需校验尺寸、类型和当前 PDF 版本。
- 有文字层时不做整页 OCR；扫描件或不可恢复二维结构应明确降级，不能伪装成精确文本。

## 论文理解、上下文与记忆

- 论文记忆分为事实层和可重建语义层：结构只引用稳定 block，摘要和画像不能覆盖原文。
- 缓存身份至少包含 paperId、PDF hash、解析版本和 schema/pipeline 版本。
- 全文理解按实际输入大小选择单次或少量大块处理；分块逐项保存检查点，修复调用不重发整篇论文。
- 当前问题优先级最高；当前选区是只用于下一条消息的可选附件；对话历史、画像和长期观察只帮助理解和检索。
- `conversationId` 定义连续对话边界。新对话使用新 ID；清除选区不清除历史；新主题不得被上一轮 evidence 压制。
- 对话历史始终提供给模型理解语境，但只有包含明确承接词的追问才把上一轮问题和 evidence block 加入本轮检索；否则只按当前问题召回，从而允许同一对话自然切换主题。
- `research_message` 用于界面恢复，`paper_conversation_turn` 保存服务端轮次，`paper_memory_observation` 只保存通过门禁的论文 claim。
- 前端已明确持有研究会话时，workbench run 必须在计划创建后、执行开始前绑定该会话；不能等回答成功并写消息时才绑定。自动历史回填只处理带有效结果的 `COMPLETED` 运行，失败、排队或运行中的审计记录不得创建用户可见的空白对话。
- 通用知识不能写成论文事实，也不应进入论文长期记忆；论文推断必须保留证据与推断属性。
- 首次执行冻结版本化上下文快照，重试只能复用同一问题、论文版本和 canonical anchor 的快照。

## 检索与证据

- RAG 的事实边界是可回到当前 PDF 的 evidence，而不是向量分数或论文画像。
- 技术论文检索混合精确标识符、关键词、章节/类型和选区邻域；当前默认实现不依赖 Embedding 或向量服务。
- 中英文混合查询必须分离汉字、拉丁/数字和希腊字母 run，保留 SINR、RSMA、SIC 等技术标识符。
- 召回以当前问题为主。窄问题找到高相关直接证据后，不应为填满数量继续加入弱旁支；广泛问题则按章节覆盖。
- 多路召回先融合排名，再按直接性、类型、位置、置信度和重复程度过滤；默认不增加一次 LLM 重排序。
- 同一原句、公式或图表的目标和支撑上下文应组成一个证据单元，避免重复页码和重复 claim。
- 只有本轮候选集内、分数有效且版本一致的 evidence ID 可以通过 Evidence Gate。
- 回答段落应直接绑定 evidence ID；不能从独立 Markdown 和 claims 中用模糊相似度猜引用位置。
- 引用覆盖率只回答“已经写出的结论是否有证据”，不能证明回答完整。普通论文问答应把用户当前问题作为有界回答契约；每个回答块显式绑定要求 ID，门禁至少检查直接问题是否被处理。不要为拆分回答要求额外调用一次模型，以免增加延迟、Token 消耗和不必要的修复。
- 回答要求必须由当前问题与本轮 evidence 动态生成，不能为 SINR、SIC、公式等具体案例写固定规则；上下文要求只保留会显著改变直接答案含义的假设、范围或限制，避免把全部相邻内容强塞进回答。
- 不同模型可能对原文短引文做空格调整或轻微改写；服务端优先在模型已绑定的 evidence ID 内选取有词项重叠的精确原文。若供应商改写了 ID，只有当原文短引句在本轮候选集中唯一命中时才可回绑真实 ID；多义或无匹配时必须拒绝。
- 一个回答块提及的技术缩写、公式编号或数学标识，若存在于所引证据中，也必须由该块的原文引句覆盖；章节标题不参与此检查，避免把 `SYSTEM MODEL` 当成待引用事实。
- 模型若把回答块明确标为 `GENERAL_KNOWLEDGE/EVIDENCE_LIMIT` 却仍附论文引用，服务端应确定性删除这些引用；不得把非论文块强改为论文事实，也不得因此触发一次昂贵但无效的模型修复。
- `EVIDENCE_LIMIT` 是内部质量判断，不是面向用户的回答内容；前端应隐藏该类回答块，但不能删除后端门禁与运行记录中的诊断信息。
- `INFERENCE` 已是结构化事实类型，前端会统一显示“据此推断”；门禁不应再强迫模型在同一段自然语言中重复“推断/可能”等字样，否则会为纯展示措辞触发昂贵且易截断的修复调用。
- 用户上传到对话的附件属于本轮辅助上下文，不属于左侧论文证据：允许帮助理解与检索，但不得生成论文 cite。优先在本地提取 PDF 与文本格式，限制文件数量、大小和进入模型的字符数，避免依赖供应商多模态能力或把二进制正文写入运行记录。
- 正文回链优先在指定页用 PDFium 查找服务端绑定的完整原句；唯一原句可覆盖可能过时的 block bbox，多义结果再用 bbox 选最近目标。不得用少量宽泛关键词冒充精确定位；失败后明确降级为段落框。
- 公式、图表和表格使用独立 target bbox；公式区域由编号/主体及同簇碎片的并集构成，支撑正文 bbox 不能冒充点击目标，单栏目标不能跨入邻栏。

## 模型与供应商

- “OpenAI-compatible”只表示协议相近，不代表 URL、Token 参数、SSE、结构化输出、推理字段和图片能力相同。
- 供应商和接入通道由能力档案管理，Base URL 不可统一删除或追加 `/v1`；模型 ID 必须允许编辑。
- 可用模型查询只使用弹窗当前的 Base URL 与 API Key 临时访问兼容的 `/models` 端点；查询结果不代表保存设置，遮罩 Key 应回退到后端已保存密钥，错误响应不得回传密钥或上游正文。
- 结构化任务使用 JSON schema/response format，并拒绝空内容、截断内容和只有 reasoning 的响应。
- 结构化响应即使正文非空，只要供应商报告 `LENGTH/MAX_TOKEN` 或输出已触顶，也必须视为截断；首次调用应使用本轮完整预算，恢复调用再按供应商实际消耗计算剩余量，不能预留预算反而截断首轮 JSON。
- Evidence Gate 只允许同一证据集修复一次；日志只保存低敏摘要、Token、耗时和稳定错误码。
- 技术术语引用校验只要求回答中的论文事实术语能在短引文中对应；章节路径中的全大写标题属于定位元数据，不能反向要求每条事实短引文重复标题词，否则会把有效回答误判为无证据。
- 回答要求由服务端从用户当前问题直接生成，不消耗模型调用；证据门禁修复复用同一要求并优先携带已引用证据，不能在修复时重新规划或随机缩小回答范围。关键上下文是否充分由回答提示和证据质量约束，不用第二个规划模型强行枚举。
- 异步任务只有在尚未进入 Evidence Gate 修复时才能安全重放模型步骤；修复依赖内存中的上一版回答，修复开始后的供应商故障必须保留原错误并终止，不能丢失前驱答案后仍沿用一次性修复计数。
- 证据门禁修复不应重放首轮完整 Prompt；只携带当前问题、失败原因、精简旧答案和已引用/高优先级证据，否则简单问答会在修复前因总 Token 预算自我拒绝。
- 强推理模型的隐藏 reasoning 会消耗 completion token；只有供应商明确支持且实测有效时才发送专有推理参数。
- 论文分块摘要、全局画像、JSON 修复和公式转写属于有界结构化抽取，不依赖深度推理；对 Kimi 使用低推理策略应映射为关闭 thinking。分块失败后不得用完全相同的输入和预算自动重放，成功分块应保留并只在用户重试时处理失败分块。
- 聊天模型不能自动充当 Embedding 模型；当前论文问答和兼容 Skill 都不得暗中增加 Embedding 或 LLM 重排调用。

## 前端交互

- PDF 对象使用 `shallowRef`，避免 Vue 深度代理破坏 PDF.js 私有字段。
- 虚拟页的渲染状态必须绑定当前 DOM 和 generation；KeepAlive 激活后等待非零布局并重绘可见页。
- SVG 标注层默认不截获文字选择，只有已有标记、拖柄、笔记/批注图标或公式模式接管指针事件。
- 笔记和批注都绑定原文，拖动只改变图标位置；批注仅在列表打开时展示，写作助手只消费笔记。
- 新拖选只形成候选；确认后作为下一条消息附件，任务被后端接受后自动卸下。切换候选、附件发送或取消选区都不能清空对话。
- 模型回答统一由安全 Markdown/KaTeX 渲染，关闭原始 HTML 和 KaTeX trust，不显示思考过程。
- 公式框选区域可能同时包含多条独立公式；视觉协议必须返回按从上到下、从左到右排序的公式数组。一个选区作为公式组持久化、逐条编辑和展示，再以组合 LaTeX 形成同一个可定位上下文锚点；旧单公式记录继续按单元素组读取。
- 已确认的公式选区属于待发送上下文，不是 PDF 点击态。普通点击、切换工具或切换选取模式不能静默清除；只有右侧关闭可以直接移除，新的文字或公式选区必须在完成拖选后询问是否覆盖，取消时恢复原固定内容。
- 论文对话输入遵循常见即时通讯习惯：Enter 直接发送，Shift+Enter 插入换行；输入法仍在组合文字时的 Enter 不得触发发送。
- 论文助手顶部应保留内容/公式选择方式与对比文献入口；文字确认后可折叠为紧凑摘要。公式的“固定内容”只负责识别并展示可编辑 LaTeX，不收起；首次“确认固定”和后续“保存校正”均只在保存成功后折叠，并允许重新展开。
- 对话中手动输入的 LaTeX 应作为可编辑的独立公式标签，而不是把 `$$...$$` 直接写进问题正文；标签按“公式1、公式2……”命名，与文件附件共同受每轮最多 3 项的限制，并作为辅助上下文而非论文 cite 发送。
- 无选区不等于无论文上下文：普通对话可以在没有 PDF 证据时回答，但“文中某公式在哪里”等明确依赖当前论文的问题必须先召回本轮证据。中文检索词应去掉提问套话，并允许常见术语映射多个候选缩写（例如“信噪比”同时尝试 SNR 与 SINR），最终由当前 PDF 的实际文本决定命中项。
- 对话历史不能因“对话框非空”就自动注入。无新选区时，只有明确指代（如“继续解释这个公式”）或当前问题与最近对话共享有意义的技术术语时，才继承旧对话与旧证据焦点；无关问题必须排除旧对话。前端“沿用对话上下文”以后端实际路由结果为准。
- 回答内角标与展开后的证据列表必须共用一份“逻辑来源”序列；同一公式的可读文本负责展示，区域证据负责跳转，两者合并成一个编号，不能重复显示页码按钮。
- 文本来源不能只按 evidence ID 去重：同一版面 block 内的不同精确引句是不同来源；相邻 block 中阅读顺序连续、同栏、几何相邻且前句未结束的引句应合并为一个跨行逻辑来源。
- 跨行逻辑来源对用户显示空格归一化后的完整句子，但给 PDFium 保留分片目标文本；搜索分别定位每个物理行片段后合并字符框，避免依赖跨行字符串是否能一次命中。
- 可执行科研命令必须由服务端白名单解析，并绑定已通过证据门禁的回答引用；前端只执行声明过的动作。自动高亮优先使用 PDFium 精确字符框，只有公式区域允许回退到公式 bbox，普通正文定位失败时不得落库。
- 高亮白名单应覆盖“找出/定位 XX 并高亮”和“将 XX（对应的区域）高亮”等直接表达；解析后清理“对应区域/内容”等操作性后缀，但仍必须以本轮已引用证据定位，不能让自由模型文本直接控制 PDF。
- 证据跳转应在目标页渲染完成后，依据已挂载页面的真实偏移和目标归一化坐标同时调整纵向/横向滚动，不能只跳到页首。
- PDF/助手只持久化宽度比例；页面不足时允许 PDF 横向滚动，不能裁掉论文内容。

## 安全、运维与验证

- 配置读取只返回脱敏值；生产缺少 `RA_MASTER_KEY` 时 fail-closed；CORS 禁止通配符。
- 文件路径必须限制在配置目录内；MySQL 与 PDF 分开备份。
- 本地论文统一存放在项目根目录 `data/papers`，数据库继续保存相对文件名。打开文献目录的接口不接受客户端路径，只能打开服务端已配置的存储根目录。
- 论文文件与数据库不能做为两条互不相关的删除链。应先在事务内删除论文及其级联数据，再在 `afterCommit` 删除 PDF 与派生资产；所有路径必须规范化并校验仍在配置根目录内，避免数据库回滚后文件已丢失或路径越界。
- health、metrics 和日志只记录低基数低敏信息，不记录密钥、论文正文、Prompt 或 Provider 响应体。
- 本地服务就绪以 3306 监听、后端 health 和前端 HTTP 响应为准，不能只相信 PID。
- 本地启停脚本只能终止其 PID 文件可追溯且进程树属于当前项目的进程；目标端口被未知进程占用时应拒绝误杀。数据库优先使用管理命令优雅关闭，超时后才终止已确认归属的进程树。
- MyBatis Plus 默认不会把实体的 `null` 字段写回数据库；承担可恢复状态机的输入、输出、错误和时间字段必须显式允许 `NULL` 更新，否则重试只会在内存中看似清空。
- 常规验证顺序为后端 `clean test`、前端单测和生产构建；PDF 变更还需真实双栏/数学论文浏览器验收。
