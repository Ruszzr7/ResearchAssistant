# Research Assistant 八阶段重设计验收

## 1. 验收边界

本文是 2026-07-19 八阶段重设计的最终真源，覆盖已确认的界面需求、交互细节和单篇论文精读工作流。缺陷分析与论文对比只保留入口，不在本轮实现；不启用云 PDF 解析，不增加 GROBID 部署依赖，也不调用真实 LLM/API 进行验收。

每一阶段均按 `Plan → Explain → Execute → Test → Review → Commit` 独立闭环，后一阶段只在前一阶段测试通过并提交后开始。

## 4. 五项确认细节

| 决策 | 最终处理 |
|---|---|
| 笔记与批注命名 | 以用户动作而不是旧存储名为准：选定内容写“笔记”，页面位置写“批注” |
| 范围修改与删除 | 不增加撤销或独立调整模式；拖错可继续拖回，× 就是删除标注 |
| 历史测试数据 | 不迁移无价值的旧笔记/标注语义；V23 直接清理并删除重复数据表 |
| PDF 解析 | 使用现有本地 PDF.js + PDFBox 及已有公式框选识别；不调用云解析，因此没有额外解析 API 费用 |
| 阅读与写作边界 | 阅读计划删除；写作助手保留，继续消费有来源的选区笔记 |

GROBID 只保留为未来可选增强方案：默认构建、启动和部署均不下载、不打包、不要求安装；若未来启用，应由部署者显式配置独立服务或外部命令，并保留 PDFBox 失败回退。这样其他人部署当前项目时无需安装 GROBID。

## 5. 单篇精读工作流与数据职责

```text
PDF 导入
  → 本地 PDFBox 解析与版面制品
  → 版本化结构事实 paper-structure-v1
  → 后台章节/语义分块理解
  → 分块摘要检查点
  → 全局论文画像 paper-understanding-v1
  → 用户选区并提问
  → 服务端上下文组装与冻结
  → 固定 Workflow 调用模型
  → Evidence Gate 校验引用
  → 回答 + 服务端对话轮次 + grounded observations
```

数据职责保持简单且可追溯：

| 数据 | 存储与职责 |
|---|---|
| PDF 文件 | 本地文件系统，原始事实载体 |
| 论文、任务、版面结构、论文画像、对话轮次、长期观察、引用元数据 | MySQL + Flyway，是持久化真源 |
| 原文分片 | MySQL 保存版本和元数据 |
| 向量 | 默认内存、可选 Qdrant，只用于候选证据召回，不作为引用真源 |
| Redis / 图数据库 / Obsidian 式全库知识库 | 当前不引入 |

上下文优先级固定为：当前问题 → 本轮选区与当前 PDF evidence → 服务端对话历史 → 当前版本论文画像 → 当前版本长期观察。只有本轮 evidence 能支撑论文事实与 citation；历史、画像和观察只帮助理解追问及检索。相同 grounded claim 可合并确认次数和证据，不同或冲突 claim 并存，回答时始终以当前 PDF 版本和本轮 evidence 为准。

Skill 用于可复用原子能力，固定 Workflow 负责执行顺序、状态、重试、token 预算和 Evidence Gate；单篇精读不采用可自行跳过质量门禁的开放式工具循环。每篇论文的理解独立按 PDF/解析版本保存，跨论文关系延后到论文对比阶段构建。
